# Feature Specs

Each feature spec uses three files:

- `requirements.md` — observable behavior and acceptance criteria.
- `design.md` — technical architecture and implementation decisions.
- `tasks.md` — ordered implementation checklist.

## Status convention

Each spec may use:
- `Draft`
- `Ready`
- `In Progress`
- `Blocked`
- `Done`

## Requirement rule

Confirmed behavior is written as a requirement.

Unknown behavior is written as `TBD`, not invented.

## Implementation rule

Do not execute unrelated tasks from another spec unless the dependency is explicit.
